# Suno 测试与开通指南

更新：2026-10-07。第一期代码已接入 Kie.ai 第三方音乐接口；未配置真实 Key，未调用真实生成，未上传录音。当前可以直接测试“本地伴奏 + 真实原声”的完整流程。

## 1. 有没有免费 API 可以测试？

| 入口 | 目前能确认什么 | 如何使用 |
| --- | --- | --- |
| [Suno 官方 Platform](https://platform.suno.com/) | 有官方 API 登录入口；公开页面未确认免费 API 额度、账号资格和完整价格。 | 有官方账号后核对 API 专属文档；当前代码不直接接这个入口。 |
| [Kie.ai](https://kie.ai/) | 首页写明新用户可获 **80 credits** 试用；没有据此确认所有新账号都能用这笔赠额调用 Suno Generate。 | 注册后在控制台核对赠额、有效期、模型可用性与生成单价，再建 Key。它是第三方，不是 Suno 官方接口。 |
| [Suno 网页免费计划](https://help.suno.com/en/articles/2410049) | 网页每天 50 credits，约 10 首歌。 | 是网页额度，不是本项目能使用的 API 额度；如账号允许下载，可本地导入。 |

建议先走本地导入验收，确认“生活声音配伴奏”方向值得继续，再开通 Kie。普通 Suno 会员的网页权益不会自动变成 API 权益。

## 2. 没有 Key，现在就能做什么？

1. 在项目目录运行 `npm run dev`，打开终端显示的地址。默认是 `http://127.0.0.1:3000`；端口占用时可能是 3001。
2. 在上方录一种生活声音，或点击“载入三种示例声音”。合成示例仅用于操作测试。
3. 点击步骤 **04 Suno 伴奏**，在“带一段伴奏进来”导入有权使用的音频。支持浏览器能解码的单/双声道音频，10～360 秒、最多 50 MiB。
4. 分别点击“只听伴奏”“只听原声轨”“一起试听”。通过试听位置选择开头、中段、结尾。
5. 如果始终早/晚一点，展开校准调整首拍；如果越来越错开，微调 BPM。不断变速的伴奏暂不适合这一版。
6. 调整“我的原声”和“整条伴奏”音量。确认原声清楚可辨、全曲不明显跑拍后，勾选确认，点击“导出原声融合版”→“保存立体声 WAV”。

低于 120 秒的伴奏只能预听，不通过循环或补静音凑两分钟。伴奏始终正常速度播放，校准只改变原声敲击的调度，不会给伴奏变调。

上方“钢琴、低音、铺底”只控制本地编曲；Suno 伴奏是整条音频，不能用这些滑块分别控制其中乐器。改伴奏风格需要重新生成或换文件。

## 3. 开通 Kie 并配置本机

1. 访问 [Kie.ai](https://kie.ai/)，自行注册并阅读适用条款。
2. 在账户中确认是否收到 80 credits、是否允许用于 Suno 音乐生成，以及当前单次费用。赠额不可用时仍可继续本地导入，暂不必充值。
3. 打开 [API Key 页面](https://kie.ai/api-key)创建 Key。不要粘贴到聊天、网页输入框或 Git。
4. 项目没有 `.env.local` 时，将 `.env.example` 复制为 `.env.local`；已有文件只补充以下字段，保留原配置：

```dotenv
# 与实际地址栏的协议、主机、端口一致，不含路径、# 锚点或尾斜杠
APP_ORIGIN=http://127.0.0.1:3000
# 自行设置独立口令，不要复用 API Key 或保留示例占位文字
DEMO_ACCESS_TOKEN=填写你自己设置的演示口令
MUSIC_API_KEY=填写你的Kie密钥
MUSIC_MODEL=V6
# 第一次联调可设为 1，确认费用与结果后再提高
MUSIC_MAX_JOBS_PER_DAY=1
MUSIC_DATA_DIR=.music-data
```

如果本机运行在 `http://127.0.0.1:3001`，上面的 `APP_ORIGIN` 也必须改成这个地址。`localhost` 和 `127.0.0.1` 不等价。不要添加 `NEXT_PUBLIC_` 前缀。

5. 重启开发服务。打开步骤 04 的“连接与开通指引”，点击“重新检查配置”。“已配置”只表示环境变量符合要求，**没有验证账号权限、余额或真实生成效果**。
6. 网页“本机演示口令”填 `DEMO_ACCESS_TOKEN` 的值。口令只留在当前页面内存，刷新后需重新输入。
7. 先选 2 分 30 秒，使用“稳定四拍、钢琴、少打击乐、自然结尾”的描述，点一次“生成一版伴奏”。待候选出现后主动选用，再按照上一节确认和导出。

应用不会代注册、自动充值或自动再次付费生成。本期只发送文字要求；原始音频和 PCM 不上传给 Kie。声音名称与工程版本会保存在本机任务快照，当前上游提示主要使用描述与 BPM。

## 4. 等待、恢复与常见问题

| 情况 | 操作 |
| --- | --- |
| 音乐服务尚未配置 | 检查三个必要变量 `MUSIC_API_KEY`、`DEMO_ACCESS_TOKEN`、`APP_ORIGIN`，重启服务；口令不能保留模板占位值。 |
| 无法验证来源或口令 | 确认网页口令一致；核对主机和端口，尤其 3000/3001。 |
| 请求被拒绝 | 在服务商控制台检查权限、赠额适用范围和余额。应用不会展示包含密钥的上游响应。 |
| 网络中断或页面刷新 | 重新输入演示口令，点击“恢复 / 刷新任务”。浏览器保存了原请求编号，服务端复用同一任务。 |
| 提交结果待确认 | 可能已扣费。保留 `.music-data`，在服务商任务记录中核对；没有上游任务编号时不能自动判断是否已收单，本版会阻止再次提交。需要人工核对后由开发者处理该任务，不要删除目录来绕过。 |
| 暂停等待 | 仅停止页面轮询，云端可能仍在生成和计费。 |
| 下载中断 | 恢复查询会重新保存同一任务的音频，不重复生成。地址失效时最多成功刷新一次地址；查询暂时失败可重试，新地址仍失效则明确失败。 |
| 旧工程版本候选 | 候选不会自动覆盖当前工程；主动选用后重新确认节拍和原声听感。 |
| 不支持的返回格式/音频域名 | 本期只接受已知协议和受限服务商音频域名。保留任务与脱敏错误，依据实际响应更新适配器，不直接放开任意 URL。 |
| 本地保存失败 | 浏览器可能禁用了存储或空间不足；先导出当前音频。不要把未保存提示当作工程已备份。 |

最多一个生成任务进行中。默认每日 12 个任务，按 UTC 日期计数；提交前预占，失败和未知状态也占用上限，以保守控制费用。它是任务数上限，不是美元预算或与服务商余额同步的账单。

## 5. 数据与实现边界

- 原始录音 PCM、当前乐谱、版本和来源在本机浏览器 IndexedDB 保存；刷新可恢复。撤销历史、未采纳提案、演示口令不长期保存。
- 浏览器 localStorage 保存最近一次生成请求/任务关联。切换主机或端口会进入另一份浏览器存储，不能当作工程丢失后继续盲目生成。
- 云端返回的音频和任务 JSON 保存在服务端 `.music-data`，已加入 `.gitignore`。音频通过同源、口令保护的路由读取。
- 本地导入的伴奏仅在页面内存，刷新需重新选择；生成候选可恢复任务后重新载入。当前不提供完整多任务历史库。
- 这是单台机器、单个 Node 进程的演示方案。关闭页面后没有常驻下载器；恢复时需要上游结果仍可获取。不适合直接按无状态多实例 Serverless 部署。
- 节拍检测只给建议，不识别调性、小节重拍或变速曲线。真实原声不由模型重新演唱，但最终听感、音高冲突、原声存在感仍需人工确认。
- 使用新接口 [Create Task](https://docs.kie.ai/suno-api/generate-music) 和 [Record Info](https://docs.kie.ai/market/common/get-task-detail)，纯器乐请求显式传 120/150/180 秒。实际完成长度以浏览器解码为准。
