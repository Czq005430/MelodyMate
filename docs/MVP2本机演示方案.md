# 本机 Codex 引导创作实施方案

**目标：** 用户从一种生活敲击声开始，按需要增加到“骨架、重音、细节”三种角色；浏览器整理录音并加入钢琴、低音和铺底，形成 120～180 秒的分段纯音乐。本机 Codex 根据用户文字和工程摘要提出乐谱修改，经用户试听、采纳后更新作品。

**入口：** 新版工作台位于 /，旧版四小节工作台保留在 /loop。新版启动与本机 Codex 接入不需要项目 .env.local 或模型 API Key；旧版 POST /api/suggest 的配置只服务旧版在线参数建议。

**当前状态：** 核心乐谱、录音整理、音频渲染、工作台与本机 Codex 已集成，90 项测试、类型检查与生产构建通过。WebMCP 在真实页面完成读取、提案、试听、采纳、撤销与过期拒绝；无注销接口的浏览器通过单次注册和当前实例转发兼容。备用交接卡也完成了实际提交与采纳。实际导出的 WAV 为 120 秒、44.1 kHz、单声道 PCM16、5,292,000 帧。真实麦克风与人工听感仍待验收，详见 [MVP2 验收记录](./MVP2验收记录.md)。

## 架构与职责

沿用 Next.js、React、TypeScript 与浏览器 Web Audio，录音使用原生 MediaRecorder。原始音频保留在当前页面内存；浏览器完成起音分析、片段调度、钢琴采样移调、混音和 WAV 导出。使用本地钢琴素材，不新增 npm 生产依赖。

Codex 复用当前对话，优先通过 WebMCP 页面工具读取摘要并提出修改；工具不可用时通过兼容交接卡读取工程摘要、填入完整 JSON 提案。用户只描述想法和试听采纳，无需手填 JSON。网页本身不自动调用云端模型 API。Codex 规划结构化乐谱，浏览器负责演奏；模型没有直接听到录音，文字规划不能等同于音频生成或音乐质量保证。

| 模块 | 职责 |
|---|---|
| lib/song-types.ts、lib/song-plan.ts | 乐谱契约、严格白名单与时长校验、三种本地初稿、分段时间、确定性原声及音符事件。 |
| lib/recording-analysis.ts | 起音检测与单音切分；匹配可靠时对齐并保留力度变化，否则明确按目标节奏重新编排。 |
| lib/song-render.ts | 原声、真实钢琴采样、合成低音及铺底的整曲与分段渲染、混音保护和取消处理。 |
| lib/use-song-studio.ts、工作台组件 | 引导录音、最多三份角色素材、版本、提案、试听、采纳、最近 5 次修改撤销与导出。 |
| lib/site-tools.ts | 注册读取摘要与提交提案工具；页面兼容交接入口使用相同的乐谱与版本约束，不接收或执行模型生成代码。 |

## 用户流程与行为契约

1. **先录一种。** 用户选择角色，查看十六格节奏示意；先倒数一小节，再录两小节。只提供视觉节拍，不外放节拍音。录音可提前结束并整理，也可取消；切到后台时取消录音。可以改用导入音频或明确标注的合成示例。
2. **听原录音与整理结果。** 轻微偏拍且与引导匹配可靠时对齐；有清晰单音但匹配不可靠时重新编排，不假称保留原演奏。没有有效敲击时提示重录。每个角色最多一份素材，重新录制会替换该角色；无需先凑齐三种声音。
3. **试听分段初稿。** 本地“温暖松弛”“轻快出发”“夜色漂浮”初稿均为 120 秒，包含原声进入、主题、展开、留白、返回和收尾。使用声部出入、节奏及力度变化、和弦连接与配器发展；用户可先听段落、再听整曲，也可单听生活声音或调整伴奏音量。
4. **由 Codex 提案。** 用户在当前 Codex 对话描述变化；Codex 先读取当前版本和摘要，再通过 WebMCP 或兼容交接卡提交完整乐谱及修改说明。页面显示提案，用户试听后采纳。两种方式均由当前 Codex 推理生成提案；本地规则初稿与手动混音不标为 AI 创作。
5. **撤销与导出。** 最近 5 次修改可撤销，没有重做。导出准备完成后由用户点击“保存 WAV”；修改后需重新导出。页面没有工程自动保存，刷新或关闭会丢失素材、提案和历史，WAV 不能恢复编辑工程。

## 乐谱与音频边界

- 固定 4/4 拍，速度 72～128 BPM，统一大调或自然小调；4～8 个段落，每段 4～32 小节且为 4 的倍数，总长校验为 120～180 秒。默认 96 BPM、48 小节为 120 秒。
- 三种角色各保存 16 格力度动机；每段可配置和弦级数、钢琴和弦或分解和弦、低音、铺底、原声角色与强度。首末段保留原声，每段必须有可发声声部；缺少对应录音角色时使用已有可用原声回退。
- 素材面向短敲击。导入文件为 0.1～12 秒、最多 10 MiB；引导录音包含倒数，最多保留 12 秒，由浏览器解码。没有视频抽音，也不保证所有编码兼容。
- 原声使用有限预增益；混音峰值保护不等于感知响度归一化。响度平衡、原声是否显著、跨段尾音和钢琴听感须用实际渲染验证。
- 钢琴为 **Salamander Grand Piano / Alexander Holm / CC BY 3.0** 的真实采样，取 C3/C4/C5 三个根音并在运行时移调、混为单声道；不是完整钢琴音源或多力度采样库。低音与铺底为合成声部。素材来源、校验值、许可和分享作品时的致谢见 [钢琴采样说明](../public/audio/piano/SOURCES.md)。
- 不提供歌词、人声演唱、长音自由伸缩、自动音高识别、修音或降噪。明确音高的原声可能与和弦冲突，用户需要试听后调整；不以算法测试替代听感判断。
- 导出单声道 44.1 kHz、16-bit PCM WAV。工程与录音只存当前页面内存，没有数据库、自动保存或可恢复工程文件。

## Codex 接入契约与验证门槛

WebMCP 页面工具为 melodymate_read_project 和 melodymate_propose_song。读取结果包含当前版本、乐谱、声音标签、测量及节奏摘要、待采纳提案状态；不包含 PCM、Blob 或凭证。兼容交接卡展示同类摘要并接收完整 JSON 提案，由 Codex 操作。摘要和用户文字会进入 Codex 对话处理，因此不把整个流程描述为完全离线。

提案必须附当前 baseRevision 和完整乐谱，经 validateSongPlan 校验字段、范围、结构及总时长。手改、换录音、撤销后，旧版本提案不得覆盖当前作品。两种接入都只生成待试听提案，不自动采纳、播放、申请麦克风或下载，也不执行模型生成的代码。

“页面工具就绪”仅表示注册状态。只有 Codex 在真实页面发现工具、读取工程、成功提交提案，且用户能在页面试听、采纳，才可记录 WebMCP 直连已验证。兼容交接路径需单独记录 Codex 实际读取与填入提案、用户试听采纳的证据，不能借它宣称直连成功。如果两种路径暂时都不可用，本地初稿与手动混音仍可使用，但不能伪造 AI 成功。
