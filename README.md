# MelodyMate

把短短的生活敲击声编成 **2～3 分钟的分段纯音乐**。先录一种声音就可以开始，再按需要加入“骨架、重音、细节”三种角色。浏览器整理录音、演奏钢琴采样与伴奏；本机 Codex 提出编曲方案，用户试听后决定是否采纳。

新版工作台位于 **/**，旧版四小节工作台保留在 **/loop**。**本地编曲、本机 Codex 和导入伴奏不需要 API Key。** 当前 Codex 对话已通过 WebMCP 在真实页面读取工程、提交编曲提案，并验证试听、采纳、撤销与过期拒绝。备用交接卡也已实际提交并采纳：工具不可用时由 Codex 操作，用户无需手填 JSON。

新增步骤 **04 Suno 伴奏**：可通过 Kie.ai 第三方接口请求 2～3 分钟器乐，或直接导入独立伴奏，再保留真实原声轨混合、校准和导出立体声 WAV。无 Key 时禁用生成，仍可测试导入流程；真实 Suno 生成和音质尚待账号联调。免费额度核实、完整开通步骤和本轮测试边界见 [Suno 测试与开通指南](./docs/Suno测试与开通指南.md)，开发清单见 [Suno 开发计划](./docs/Suno开发计划.md)。

此前本地编曲已确认导出 120 秒、44.1 kHz、单声道 PCM16，共 5,292,000 帧。原新版范围见 [MVP2 本机演示方案](./docs/MVP2本机演示方案.md)，历史证据见 [MVP2 验收记录](./docs/MVP2验收记录.md)。真实麦克风与人工听感仍待现场验收，不能以合成示例替代。

## 本地启动

需要 Node.js 24 或更高版本和 npm。录音需要支持 MediaRecorder 的浏览器，以及本机回环地址或 HTTPS。WebMCP 直连还需要浏览器宿主支持页面工具。

1. 在项目目录执行 npm ci，按锁文件安装依赖。
2. 执行 npm run dev，打开 http://127.0.0.1:3000。
3. 可以先载入合成示例，检查本地创作流程。与 Codex 协作时，在 Codex 浏览器中打开页面并继续当前对话。

常用脚本：

~~~bash
npm test
npm run typecheck
npm run check
npm run build
npm run dev
~~~

npm run check 依次执行测试和类型检查。生产模式先运行 npm run build，成功后运行 npm run start。新版无需为以上启动流程配置旧版 /api/suggest。

## 新版创作流程

1. **收集第一种声音。** 选择“骨架”，跟随页面亮格敲桌面或木块。点击“开始引导录音”后先倒数一小节，再录两小节；仅有视觉引导，不外放节拍声。可以提前“结束并整理”或“取消录音”。也可导入短音频，或使用明确标注的合成示例。
2. **比较整理结果。** 分别点击“听原录音”和“听整理后的节奏”。轻微偏拍且匹配可靠时对齐到目标节奏；匹配不可靠但有清楚单音时，用这些单音重新编排，并说明没有保留原演奏节奏。无有效敲击时需要重录。需要更丰富的声音时，再录“重音”和“细节”；每种角色最多保留一份录音。
3. **试听本地初稿。** 选择“温暖松弛”“轻快出发”或“夜色漂浮”，先听段落，再播放整曲。三种初稿均为 120 秒，有原声进入、主题、展开、留白、返回与收尾。钢琴、低音与铺底音量可调整，也可“只听生活声音”。这些初稿由本地规则产生，不是 AI 结果。
4. **让 Codex 提出变化。** 在当前 Codex 对话中描述想法，例如“开头保留我的桌面声，中间更有节奏，结尾安静下来”。Codex 优先通过 WebMCP 读取当前工程、提交提案；若页面工具不可用，则由 Codex 展开兼容交接卡、读取摘要并填入完整 JSON 提案，用户无需操作技术字段。两种方式都使用当前 Codex 的推理结果，页面显示提案后仍由用户试听、采纳，不自动覆盖作品。未收到实际提案时不能视为已经使用 AI。
5. **尝试独立伴奏。** 在步骤 04 描述想要的器乐与感觉，配置 Kie 后生成候选；没有 Key 也可导入伴奏。分别听原声/伴奏/混合，检查开头、中段和结尾。校准固定拍速与首拍后勾选确认，再导出融合版。伴奏实际不足 120 秒时仅供预听，不作为完整两分钟作品。
6. **保留满意的作品。** 支持最近 5 次修改的撤销。当前原声录音与乐谱自动保存到本机浏览器，刷新后恢复；撤销历史与未采纳提案不保存。本地编曲使用“导出整曲”→“保存 WAV”；独立伴奏使用“导出原声融合版”→“保存立体声 WAV”。修改后需重新导出；本地导入伴奏刷新后需重新选择，生成候选可恢复任务后重新载入。

如果暂时无法通过任何方式接收 Codex 提案，仍可使用本地初稿和手动混音完成作品；这些操作不会标为 AI 创作。

## 新版能力与边界

- 面向短敲击、拍手、短摇动等素材。导入文件为 0.1～12 秒、最多 10 MiB，由浏览器解码；不包含视频抽音，不保证所有音频编码兼容。引导录音按当前速度录两小节，连同倒数最多保留 12 秒。
- 固定 4/4 拍，速度 72～128 BPM；乐谱为 4～8 段，每段 4～32 小节且为 4 的倍数，总长必须在 120～180 秒。通过声部出入、节奏与力度变化、和弦及配器发展形成结构；不提供歌词或人声演唱。
- 原声以切出的单次片段承担节奏角色，不做长音自由伸缩、降噪、音高识别或自动修音。杯子等带明确音高的声音可能与伴奏冲突，需要试听后改调或降低伴奏。
- 钢琴使用 **Salamander Grand Piano** 的真实录音，作者 **Alexander Holm**，采用 **CC BY 3.0**；目前使用 C3/C4/C5 三个根音移调，并非完整钢琴音源或多力度采样库。低音与铺底使用合成波形。来源、许可、改动说明及分享作品时的致谢见 [钢琴采样说明](./public/audio/piano/SOURCES.md)。
- Codex 负责理解文字和规划乐谱，音频由浏览器渲染。模型没有通过摘要或交接卡听到录音；声音标签与测量摘要不能证明声源物体或音高，也不保证编曲听感。
- WebMCP 提供 melodymate_read_project 与 melodymate_propose_song：读取当前版本、乐谱与声音摘要，提交带版本的完整提案。兼容交接卡通过页面读写同类数据，仍需校验乐谱与版本。换录音、手改或撤销后旧提案不得覆盖新版本；不执行模型生成代码，不自动申请麦克风、播放、采纳或下载。
- 原始 PCM 与录音 Blob 不通过页面工具、交接卡或音乐 API 上传；文本、测量摘要和乐谱会由 Codex 对话处理。新增音乐 API 将文字风格要求与 BPM 发给 Kie，不能把整个创作流程称为完全离线。
- 本地编曲导出单声道 WAV，独立伴奏融合版导出双声道 WAV，均为 44.1 kHz、16-bit PCM。原声采用有限预增益，混音有峰值保护；这不是感知响度归一化，也不能代替真实录音与听感验收。
- 当前工程与原始录音自动保存到 IndexedDB；最近一次生成请求关联在 localStorage；任务 JSON 与返回音频在服务器私有 `.music-data`。没有用户账户、跨设备同步、完整历史库、工程下载、重做或云端分享。API 服务仅用于单个本机 Node 进程，暂不适合多实例部署。

## Suno 伴奏接入（可选）

仅接入 Kie.ai 第三方新版 `ai-music-api/generate`，不使用 Suno 网页 Cookie 或逆向接口。配置 `.env.local` 中的 `MUSIC_API_KEY`、独立 `DEMO_ACCESS_TOKEN` 与准确的 `APP_ORIGIN`，重启后在网页只填写演示口令。不要把 API Key 粘贴到页面或聊天。

`MUSIC_MODEL` 默认 `V6`，`MUSIC_MAX_JOBS_PER_DAY` 默认 12，初次联调建议设为 1。提交前保存请求编号并预占预算；失败和未知状态仍占额度，恢复任务不重新生成。最多一个在途任务，任务数按 UTC 日期统计。这些限制不是服务商的收费金额保证。

接口为 `GET /api/music/config`、`POST /api/music/jobs`、`GET /api/music/jobs/:id`、`GET /api/music/jobs/:id/audio/:index`。除只读配置外均要求同源与 `x-demo-token`；私有任务目录已忽略，不应放入 `public` 或提交。详细步骤及账户到位后的验收清单见 [开通指南](./docs/Suno测试与开通指南.md)。

## 旧版 /loop：四小节参数助手

旧版保留“选声音 → 排节奏 → 找感觉 → 导出”的流程，制作 8～12 秒音乐小品。它使用单一 50～500 ms 原声片段、16 格底稿与四小节编排，支持两个可试听方向、参数修改和需要用户许可的少量和弦伴奏。素材上限为 10 秒、10 MiB，录音约 2 秒；这些限制仅适用于旧版。

旧版可直接使用本地预置和手动编辑。**只有需要旧版在线参数建议时，才配置下面的 API 环境变量。** 将 .env.example 复制为 .env.local；真实密钥只放本机配置，不提交到 Git、粘贴到页面或写入日志。

| 配置 | 旧版用途 |
|---|---|
| APP_ORIGIN | 浏览器访问的完整来源，默认 http://127.0.0.1:3000；协议、主机、端口必须一致，不加路径或尾斜杠。localhost 与 127.0.0.1 不等价。 |
| DEMO_ACCESS_TOKEN | 独立演示口令；服务端未配置时拒绝 API 请求，不能复用模型密钥。 |
| MODEL_API_URL | 完整聊天接口 URL；现有 TokenHub 配置示例为 https://tokenhub.tencentmaas.com/v1/chat/completions。 |
| MODEL_API_KEY | 仅服务端使用的模型密钥，通过 Bearer 认证发送，不使用 NEXT_PUBLIC_ 前缀。 |
| MODEL_NAME | 当前账号实际已开通的模型 ID。 |
| TRUST_PROXY | 默认 false，所有来源共享限频；仅当受控代理覆盖 X-Real-IP 时设为 true。 |

旧版“创作设置”只接收演示口令，口令保留在当前页面内存；不要填入模型密钥。模型只接收文字、工程参数与测量指标，返回白名单参数建议，不接收原始音频，不生成完整歌曲。预置方向明确标注，文字修改需要真实模型连接。

POST /api/suggest 校验来源、演示口令、实际请求体大小和编辑范围；模型调用非流式、10 秒超时、最多 1024 输出 Token，不自动重试。失败时仅探索可降级为本地预置；访问拒绝不会伪装为 AI 成功。每分钟 10 次请求、最多 2 路在途调用的保护仅在单个 Node 进程内生效，尚不能作为多实例部署的全局限流。

旧版 TokenHub 接入状态、真实录音与下载测试以 [MVP 验收记录](./docs/MVP验收记录.md) 为准，不沿用为新版的验收结果。旧版设计依据见 [MVP 架构](./docs/软件架构设计-MVP.md)。
